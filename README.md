# محوّل PDF ⇄ Word

موقع لتحويل الملفات بين PDF و Word (.docx) في الاتجاهين، مع الحفاظ الكامل على
محتوى الملف الأصلي (النص، الجداول، الصور) دون أي تغيير — فقط تغيير الصيغة.
الواجهة متعددة اللغات (عربي، إنجليزي، فرنسي، إسباني، ألماني) عبر زر عائم لتغيير
اللغة في أسفل الصفحة.

تم اختبار المشروع فعليًا في هذه الجلسة: تشغيل الخادم، تحويل ملف PDF حقيقي
(نص وجدول) إلى Word والتأكد سطرًا بسطر أن كل المحتوى وصل سليمًا 100%، وتحويل
ملف Word إلى PDF والتحقق من نفس الشيء، بالإضافة إلى اختبار حالات الملفات
المحمية بكلمة مرور، والملفات غير المدعومة، والملفات الممسوحة ضوئيًا (OCR)،
وتبديل اللغة والتأكد من حفظها بين الزيارات.

## الميزات

- **تحويل ثنائي الاتجاه**: ارفع ملف PDF فتحصل على Word، أو ارفع ملف Word (doc/docx)
  فتحصل على PDF — يُكتشف الاتجاه تلقائيًا من نوع الملف، بدون الحاجة لاختيار وضع.
- **5 لغات للواجهة**: العربية (RTL) والإنجليزية والفرنسية والإسبانية والألمانية،
  عبر زر 🌐 عائم يحفظ اختيار المستخدم لزياراته القادمة.
- **دون أي تغيير في المحتوى**: النص والجداول والصور تبقى كما هي، فقط الصيغة
  تتغيّر.
- **خصوصية**: حذف تلقائي لكل الملفات من الخادم بعد التحويل مباشرة.

## كيف يعمل التحويل؟

1. **PDF → Word (ملفات نصية عادية):** يستخدم الموقع محرك **LibreOffice**
   (مثبّت محليًا على الخادم، يعمل بصمت في الخلفية) لقراءة النص الحقيقي داخل
   الملف وإعادة بنائه كمستند Word، دون تعديل حرف واحد من المحتوى.
2. **Word → PDF:** اتجاه مدعوم أصليًا وموثوق جدًا في LibreOffice (تصدير Writer
   إلى PDF)، فالناتج مطابق تمامًا لمحتوى ملف Word الأصلي.
3. **ملفات PDF الممسوحة ضوئيًا (صور فقط، بلا نص):** يكتشف الموقع هذه الحالة
   تلقائيًا، ويعرض على المستخدم خيار «التعرف الضوئي على النص (OCR)» — وهو خيار
   منفصل واضح، لأن التعرف الضوئي «يتعرّف» على الحروف من الصورة وقد يحتوي على
   أخطاء طفيفة بحسب جودة المسح، بخلاف التحويل المباشر للنص الحقيقي الذي لا يغيّر
   شيئًا. لغة التعرف الضوئي تُختار تلقائيًا حسب لغة الواجهة المُفعّلة (عربي،
   إنجليزي، فرنسي، إسباني، ألماني).
4. **ملفات محمية بكلمة مرور أو تالفة أو بصيغة غير مدعومة:** تُكتشف قبل
   المحاولة، وتظهر للمستخدم رسالة واضحة مترجمة للغته الحالية بدل خطأ تقني.
5. تُحذف كل الملفات المرفوعة والملفات الناتجة تلقائيًا من الخادم بعد التنزيل
   مباشرة (ولا تبقى محفوظة أكثر من دقيقة واحدة بعد إرسالها للمستخدم).

## التشغيل محليًا (بدون Docker)

يتطلب تثبيت: Python 3.10+، وLibreOffice، وTesseract OCR (مع حزم اللغات
المطلوبة)، وPoppler.

```bash
# على Ubuntu/Debian
sudo apt-get install libreoffice tesseract-ocr \
    tesseract-ocr-ara tesseract-ocr-fra tesseract-ocr-spa tesseract-ocr-deu \
    poppler-utils

cd backend
pip install -r requirements.txt
python app.py
```

ثم افتح المتصفح على `http://localhost:8000`.

## التشغيل عبر Docker (الطريقة الموصى بها)

```bash
docker build -t pdf2word-app .
docker run -p 8000:8000 pdf2word-app
```

هذا يجهز كل شيء تلقائيًا (LibreOffice + Tesseract بكل حزم اللغات + المكتبات)
داخل صورة واحدة، وهي نفس الصورة التي يمكن نشرها مباشرة على أي منصة استضافة
تدعم Docker.

## النشر على الإنترنت (جعل الموقع متاحًا للجميع)

أسهل الخيارات المجانية/الرخيصة التي تدعم Docker مباشرة:

- **Render.com** — يكتشف الـ `Dockerfile` تلقائيًا، فقط اربط المستودع واختر
  "Web Service". لديه خطة مجانية للبداية.
- **Railway.app** — نفس الفكرة، رفع سريع من GitHub.
- **VPS خاص** (Hetzner, DigitalOcean, Contabo…) — الأنسب على المدى الطويل من
  حيث التكلفة عند زيادة عدد المستخدمين، مع تشغيل `docker run` خلف Nginx
  كـ reverse proxy وشهادة SSL مجانية عبر Let's Encrypt/Certbot.

بعد النشر، اربط اسم نطاق (دومين) خاص بك بالخدمة لإعطاء الموقع طابعًا احترافيًا.

## اعتبارات مهمة قبل الإطلاق للجمهور

- **الحد الأقصى لحجم الملف** حاليًا 50 ميغابايت (`MAX_CONTENT_LENGTH` في
  `app.py`)، يمكن تعديله حسب قدرة الخادم.
- **عدد التحويلات المتزامنة**: LibreOffice لا يتحمّل عددًا كبيرًا من العمليات
  المتوازية على نفس الخادم، لذلك يحدّ الكود من التحويلات المتزامنة (متغيّر
  `MAX_CONCURRENT_CONVERSIONS`، القيمة الافتراضية 2). ارفعها تدريجيًا فقط بعد
  اختبار أداء الخادم الفعلي.
- عند الانتقال للإنتاج استُخدم بالفعل `gunicorn` (داخل `Dockerfile`) بدل خادم
  التطوير المدمج في Flask.
- **إضافة لغة جديدة للواجهة مستقبلاً**: أضف مفتاحًا جديدًا في `frontend/i18n.js`
  (نسخ كتلة لغة موجودة وترجمتها)، ثم أضف زر اللغة في `index.html` ضمن
  `#lang-menu`. لا حاجة لتعديل أي شيء آخر.

## المرحلة القادمة (بعد التأكد من عمل الموقع بشكل صحيح)

كما هو مخطَّط:

1. **تطبيق جوّال (Android/iOS)** يستهلك نفس الـ API الحالي (`/api/convert`)
   — لا حاجة لإعادة بناء محرك التحويل، فقط واجهة جديدة تتصل بنفس الخادم.
2. **الإعلانات**: يمكن دمج Google AdSense (للويب) أو AdMob (للتطبيق) بسهولة في
   الواجهة الحالية دون التأثير على منطق التحويل.
3. **الدفع/الاشتراكات**: للسوق الجزائري تحديدًا، خيارات مثل **Chargily Pay**
   (بوابة دفع جزائرية تدعم CIB/EDAHABIA) عملية أكثر من Stripe (غير متاح في
   الجزائر حاليًا). يمكن إضافة نظام حسابات بسيط + حد شهري مجاني + خطة مدفوعة
   لإزالة الحدود (مثل حجم الملف الأقصى أو عدد التحويلات).

هذه الميزات لم تُضف بعد بناءً على الاتفاق: أولاً التأكد من أن التحويل نفسه يعمل
بشكل احترافي وموثوق، ثم إضافة الإعلانات أو الدفع لاحقًا.
